# docs

Робочі документи проєкту. Живуть у git поруч із кодом, тож версіонуються разом
із ним і видно в PR.

## Структура

```
docs/
  specs/    що і навіщо будуємо. З кодом й з назвами файлів.
  plans/    як саме будуємо. Кроки, файли, порядок, перевірка.
```

## Порядок роботи

1. **Brainstorm** — розмова в чаті. Мета: витягти назовні припущення й межі,
   поки вони ще дешеві. Нічого не пишемо в файли.
2. **Spec** → `docs/specs/<тема>.md`. Задача, критерії готовності, що поза
   межами. Мовою предметної області, не мовою Django.
3. **Plan** → `docs/plans/<тема>.md`. Конкретні кроки, файли, що чим
   перевіряється. Спирається на спеку.
4. **Implement** — код за планом.

Після кожного етапу — зупинка й погодження.

## Правило іменування

`<тема>.md` в обох теках, однакова назва: `frontend.md` у specs і в plans — це
спека й план однієї роботи.
